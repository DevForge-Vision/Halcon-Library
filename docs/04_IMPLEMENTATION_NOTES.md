### 2.1 왜 OpenCV 를 쓰지 않았나

Phase 1 다섯 종은 **OpenCV 를 쓰면 오히려 값이 틀린다.**

| OpenCV 함수 | 왜 못 쓰는가 |
|---|---|
| `cv::arcLength` | **근사 폴리곤 길이**다. HALCON 의 "축평행 1 / 대각 √2" 체인 정의(정의서 §2.3)와 불일치 |
| `cv::contourArea` | **폴리곤 면적**이다. CV-1 결론(hull 픽셀 개수)과 불일치. 정사각형에서 `Convexity = 1.0203` 이 되어 Assertion 위반 |
| `cv::findContours` | 반환 좌표가 근사 폴리곤이라 체인 스텝을 셀 수 없음 |

결과적으로 Phase 1 은 **외부 의존성이 0** 이다. 어떤 컴파일러에서도 빌드·검증되고,
사용처의 OpenCV 버전과 충돌할 여지가 없다.

### 2.2 성능 설계

- `area_center` 는 **O(런 수)**. 열 좌표 합을 등차수열 합 `(colBegin+colEnd)·개수/2` 로 상수시간 처리.
  픽셀 순회(O(면적)) 대비 두 자릿수 빠르다.
- `FeatureContext` 가 area/center · contour · convexHull 을 **처음 요청될 때 1회만** 계산하고 캐시한다.
  `circularity` 와 `compactness` 를 연달아 호출해도 contour 는 한 번만 만든다.

### 2.3 방어 설계

- 공개 API 밖으로 **예외를 던지지 않는다.** 내부 `try-catch` → 빈 리전 규약(`0` 반환)으로 축약.
- 빈 리전 · 단일 픽셀 · 1픽셀 두께 · 빈 컨투어 · `max == 0` 전부 가드.
- **`Convexity` 에 1.0 클램프를 일부러 넣지 않았다.**
  클램프하면 `F_c` 를 폴리곤 면적으로 잘못 계산했을 때(1.0203) 1.0 으로 덮여
  **CV-1 회귀를 영원히 감지할 수 없기 때문**이다. Assertion 검사(T-6)가 이를 잡는다.

## 3. ⚠ 가장 중요한 교훈 — 곡선 도형의 기댓값을 연속 기하로 잡으면 안 된다

`docs/03_VERIFICATION.md` 초판은 링(S3)의 `ContLength` 기댓값을 **`2πR = 314.16`** 으로 잡았다.
**이것은 틀렸다.** 실측은 **`329.71`** 이고, 구현이 옳다.

### 원인 — 디지털 원의 체인코드 편향

반지름 `R` 인 디지털 원의 8-연결 체인 길이는 연속 원주보다 **약 +5.5% 크다.**
이것은 오차가 아니라 **이산 기하의 성질**이다.

1/8 옥탄트(45°)에서 체인은 축평행 스텝과 대각 스텝으로만 이동한다.

```
옥탄트 1개당 이동량 :  축평행 0.414R × 1  +  대각 0.414R × √2  =  0.828R
전체 8 옥탄트       :  8 × 0.828R  =  6.63R
연속 원주           :  2πR         =  6.283R

비율 = 6.63 / 6.283 ≈ 1.055     → +5.5%
```

R = 50 을 넣으면 `6.63 × 50 = 331.4`, 실측 `329.71` 과 부합한다.

### 이 편향의 파급

| 값 | 영향 |
|---|---|
| `compactness` | `L²` 이므로 편향이 **제곱으로 증폭**된다. S2 원판이 `1.0` 이 아니라 **`1.1027`** 이 나온다 |
| `circularity` | 영향 없음 (L 을 안 쓴다). 다만 디지털 원판의 실제 면적이 7854 가 아니라 **7845** 라 `0.9989` 로 클리핑이 발동하지 않는다 |
| `convexity` | 영향 없음 |

### 규칙 (앞으로 모든 오퍼레이터에 적용)

> **곡선 도형의 기댓값은 연속 기하 공식으로 잡지 말고,
> 이산 정의를 그대로 적용한 값으로 잡는다.**
>
> 연속 기하값은 **참고(NOTE)** 로만 남기고, PASS/FAIL 판정에 쓰지 않는다.
> 대신 **판별력이 확실한 이산 도형**(정사각형·직선·단일픽셀)으로 판정한다.

테스트는 이 규칙에 따라 두 층으로 나눴다.

- **HARD 검사**: 이산 도형의 정확값 대조 + 방향성 판별(예: `S3 ContLength < 400` — 구멍 제외 확인)
- **NOTE**: 연속 기하 대비 편차 기록. 실패로 치지 않는다

## 4. 문서 보정 4건

실측에 맞춰 `docs/03_VERIFICATION.md` 를 보정했다.

| # | 항목 | 초판(연속 기하) | 실측(이산 정의) | 사유 |
|---|---|---|---|---|
| 1 | S3 링 `ContLength` | 314.16 | **329.71** | 체인코드 +5.5% 편향 (§3) |
| 2 | S2 원판 `ContLength` | (미기재) | **329.71** | 동일 |
| 3 | S2 원판 `Compactness` | 1.0 | **1.1027** | L 편향이 제곱 전파 |
| 4 | S2 원판 `Circularity` | 1.0 (클리핑 발동) | **0.99886** | 디지털 원판 면적이 7854 가 아니라 7845 → 클리핑 미발동 |

### 4-1 의 파생 — 클리핑 검증 도형이 없다

초판은 S2 원판이 `min` 클리핑을 발동시킬 것으로 봤으나, 실제로는 발동하지 않는다.
즉 **S1~S7 중 함정 #1(`circularity` 의 `min` 클리핑)을 실제로 트리거하는 도형이 없다.**

대신 **T-6 Assertion 검사**를 추가했다 — 7개 도형 × 4개 Assertion = 28건.

```
0 <= Circularity <= 1
Compactness >= 1  또는  == 0
Convexity <= 1                 ← CV-1 회귀 감지
ContLength >= 0
```

클리핑 방향을 반대로 짜거나(함정 #1·#2), `convexity` 분자/분모를 뒤집거나(함정 #3),
`F_c` 를 폴리곤 면적으로 계산하면(CV-1) 이 검사에서 즉시 걸린다.

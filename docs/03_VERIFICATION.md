## 1. 검증 3단계

| 단계 | 방법 | 산출물 | 필요 환경 |
|---|---|---|---|
| **V1. 손계산** | 해석적으로 값이 결정되는 기준 도형에 정의서 수식을 대입 | 기댓값 표 (§3) | 없음 |
| **V2. HALCON 실측** | HDevelop 에서 동일 도형을 만들어 오퍼레이터 실행 | 실측값 표 (§4) | HALCON 13 (HDevelop) |
| **V3. 구현 대조** | C++ 단위테스트 결과를 V1/V2 와 비교 | 테스트 리포트 | 구현 후 |

- **V1 과 V2 가 다르면 정의서가 틀린 것이다.** 정의서를 고치고 다시 V1 부터 한다.
- V2 를 못 하는 환경이면 V1 만으로 진행하되, **불일치 위험 항목을 명시**하고 넘어간다.
- V3 는 V1/V2 가 합의된 뒤에만 의미가 있다.

### 허용 오차

| 값의 성격 | 허용 오차 | 이유 |
|---|---|---|
| 정수 (Area, 픽셀 개수) | **완전 일치** | 오차가 있으면 정의가 다른 것이다 |
| 무게중심 (Row, Column) | `1e-9` | 유한합의 나눗셈, 부동소수 오차만 허용 |
| 윤곽 길이 (ContLength) | **완전 일치** (√2 항 포함 후 `1e-9`) | 체인코드는 이산 합이다 |
| 형상계수 (원/링 등 곡선 도형) | 이론값 대비 `±2%` | 이산화 오차가 본질적으로 존재 |
| 형상계수 (직선 도형) | `1e-9` | 이산화 오차 없음 |

### 2B. 2차 배치에서 추가한 판별 도형 (3종)

**S1~S7 만으로는 2차 모멘트 계열의 핵심 분기를 하나도 판정할 수 없다.**
S1~S7 은 **전부 대칭 도형**이고(S5 L자조차 반대각선 대칭이다), 크기가 다른 같은 도형 쌍이 없다.
그래서 판별 목적이 명확한 도형 3종을 추가했다. **기준 도형을 늘린 것이 아니라 판별용이다.**

| ID | 이름 | 정의 | 무엇을 판정하는가 |
|---|---|---|---|
| **S1b** | 정사각형 50×50 | `row ∈ [0,49]`, `col ∈ [0,49]` | **스케일 불변성.** S1 과 짝을 지어 `moments_region_2nd_invar`(불변) 와 `moments_region_2nd`(16배 차이)를 값으로 갈라낸다 |
| **S4T** | 세로선 100×1 | `col = 50`, `row ∈ [0,99]` | **`EA-2`**(`Phi = −π/2` 처리) + `Rb = 0` 이 가로/세로 양쪽에서 나오는지 |
| **S8** | 비대칭 아령 | (작은 사각) `row ∈ [0,9] × col ∈ [0,9]` ∪ (큰 사각) `row ∈ [30,49] × col ∈ [30,49]` | **`OR-1`·`OR-3`**(`orientation_region` 의 `+π` 분기). 최원 윤곽점이 **유일**한 유일한 도형. 덤으로 `M11 ≠ 0` · 다중 연결성분 · 정확한 정수 기댓값 |

> **S8 설계 의도** — 두 정사각형을 **크기가 다르게** 대각으로 배치했다.
> - 크기가 다르므로 **비대칭** → 최원 윤곽점이 `(0,0)` 하나로 유일하게 결정된다 (`OR-3` 회피)
> - 대각 배치라 `M20 = M02`, `M11 > 0` → `Phi = −π/4` 가 **정확히** 떨어진다
> - 좌표를 고르게 잡아 `Ra = 41`, `Ia = 210125`, `Ib = 14125` 가 **정확한 정수**로 나온다
>   → 곡선 도형처럼 "±2%" 로 얼버무릴 필요가 없다 (`04_IMPLEMENTATION_NOTES.md` §3 규칙 준수)
> - 8-연결 성분이 2개 → 모멘트가 성분 분리와 무관하게 전체 합인지 함께 확인된다

### T-2. `contlength` ⚠ 최대 쟁점

정의서 미결 쟁점 **C-1**(윤곽 체인이 픽셀 중심 경로인가 픽셀 경계 둘레인가)을 판정한다.

**가설 A — 픽셀 중심 체인 (정의서 채택안)**
S1 정사각형의 경계 픽셀을 순회하면 `(0,0)→(0,99)→(99,99)→(99,0)→(0,0)`
= `99 + 99 + 99 + 99 = 396` 스텝, 전부 축평행.

**가설 B — 픽셀 경계 둘레**
`4 × 100 = 400`.

| 도형 | 가설 A | 가설 B | 판별력 |
|---|---|---|---|
| S1 정사각형 | **396.0** | 400.0 | ✅ 4 차이, 명확히 구분됨 |
| S4 가로선 | **198.0** | 202.0 | ✅ |
| S6 단일픽셀 | **0.0** | 4.0 | ✅ 가장 명확 |

> **판정 방법**: HALCON 에서 S6(단일 픽셀)의 `contlength` 를 찍는다.
> `0` 이면 가설 A, `4` 면 가설 B 다. **한 번의 실측으로 확정된다.**

**S3 링 — 구멍 처리 검증 (함정 #4)**

원문 Attention: *"The contour of holes is not calculated."*

| 해석 | 기댓값 (이산 체인) | 참고: 연속 기하 |
|---|---|---|
| **외곽만 (원문)** | **329.71** ✅ 실측 | `2π·50 = 314.16` |
| 구멍 포함 (오구현) | ≈ 495 | `2π·50 + 2π·25 = 471.24` |

> ### ⚠ 연속 기하로 기댓값을 잡으면 안 된다
> 초판은 이 값을 `2πR = 314.16` 으로 잡았으나 **틀렸다.** 실측은 **329.71** 이다.
>
> 반지름 `R` 인 디지털 원의 8-연결 체인 길이는 연속 원주보다 **약 +5.5% 크다.**
> 오차가 아니라 이산 기하의 성질이다. 1/8 옥탄트에서
> `축평행 0.414R×1 + 대각 0.414R×√2 = 0.828R`, `×8 = 6.63R` vs `2πR = 6.283R` → `+5.5%`.
> `R=50` → `331.4`, 실측 `329.71` 과 부합.
>
> **판정은 연속 기하값이 아니라 방향성으로 한다: `ContLength < 400` 이면 외곽만이다.**
> 자세한 내용은 [`docs/04_IMPLEMENTATION_NOTES.md`](04_IMPLEMENTATION_NOTES.md) §3.

### T-3. `circularity`

```
C = min(1, F / (max² · π))
```

**S1 정사각형**
```
중심   = (49.5, 49.5)
max    = 모서리 (0,0) 까지 = sqrt(49.5² + 49.5²) = 49.5·√2 = 70.003571
max²   = 4900.5
분모   = 4900.5 · π = 15395.3748
C      = 10000 / 15395.3748 = 0.6495452
```
| 도형 | 기댓값 | 실측 | 근거 |
|---|---|---|---|
| **S1 정사각형** | **0.6495452** | `0.649545732` ✅ | 위 계산. 오차 `1e-9` (직선 도형) |
| **S2 원판** | **0.99886** | `0.998856423` ✅ | 디지털 원판 실제 면적은 7854 가 아니라 **7845** → 클리핑 미발동 |
| **S3 링** | **≈ 0.75** | `0.749174148` ✅ | `A = π(50²−25²) = 5890.5`, `max = 50` → `5890.5/7853.98 = 0.75` |
| **S4 가로선** | **0.0129909** | `0.012990915` ✅ | `max = 49.5`, `49.5²·π = 7697.69`, `100/7697.69` |
| **S6 단일픽셀** | **0.0** | `0.0` ✅ | `max = 0` → 0 나눗셈 → 0 반환 (방어 규약) |
| **S7 빈 리전** | **0.0** | `0.0` ✅ | |

> ⚠ **초판 보정**: S2 를 `1.0`(클리핑 발동)으로 잡았으나 실제로는 발동하지 않는다.
> 즉 **S1~S7 중 함정 #1(`min` 클리핑)을 트리거하는 도형이 없다.**
> 대신 **T-6 Assertion 검사**(7도형 × 4항목 = 28건)로 클리핑 방향 오류를 잡는다.

### T-4. `compactness`

```
C = max(1, L² / (4·F·π))
```
**`contlength` 결과에 연쇄 의존**하므로 T-2 확정 후 계산한다.

**S1 정사각형** (가설 A, L = 396)
```
L²     = 156816
분모    = 4 · 10000 · π = 125663.706
C'     = 156816 / 125663.706 = 1.2479019
C      = max(1, 1.2479019) = 1.2479019
```

| 도형 | 기댓값 | 실측 | 비고 |
|---|---|---|---|
| **S1 정사각형** | **1.2479019** (L=396) | `1.247902078` ✅ | 경계둘레였다면 1.2732395 (L=400) |
| **S2 원판** | **1.1027** | `1.102681041` ✅ | ⚠ 초판은 1.0. **L 의 +5.5% 편향이 제곱으로 전파**된 결과 |
| **S4 가로선** | **31.1966** (L=198) | `31.197551945` ✅ | |
| **S5 L자** | 1.6590 | `1.658950491` ✅ | L=395.414 (`√2` 항 등장 확인) |
| **S6 단일픽셀** | **1.0** | `1.0` ✅ | `L=0, F=1` → `C'=0` → `max(1,0)=1.0` 로 확정 |
| **S7 빈 리전** | **0.0** | `0.0` ✅ | Assertion 이 `>=1.0 \|\| ==0` 이므로 0 |

> **함정 #2(`max` 클리핑, circularity 와 방향 반대) 검증**은 S1 이 담당한다.
> `min` 을 쓰면 S1 이 1.0 으로 나와 즉시 드러난다.

### T-5. `convexity` ⚠ 최대 쟁점 (CV-1)

```
C = F_o / F_c
```
정의서 미결 쟁점 **CV-1**(`F_c` 가 폴리곤 면적인가 픽셀 개수인가)을 판정한다.

**S1 정사각형이 결정적 시험이다.**

| 해석 | `F_c` | `C = 10000 / F_c` | Assertion `<= 1` |
|---|---|---|---|
| **픽셀 개수** (정의서 잠정 채택) | 10000 | **1.0000** | ✅ 통과 |
| 폴리곤 면적 (`cv::contourArea`, 픽셀 중심 기준) | 99×99 = 9801 | 1.0203 | ❌ **위반** |

> **판정**: S1 에서 `1.0` 이 나오면 픽셀 개수, `1.02` 가 나오면 폴리곤 면적이다.
> HALCON 은 Assertion 이 `Convexity <= 1` 이므로 **픽셀 개수가 거의 확실**하지만, 실측으로 확정한다.
> 실무적으로도 `cv::contourArea` 를 쓰면 볼록 도형에서 1을 넘어 **모든 형상계수 스코어가 오염**된다.

| 도형 | 기댓값 (픽셀 개수 해석) | 근거 |
|---|---|---|
| **S1 정사각형** | **1.0** | 볼록 도형 |
| **S2 원판** | **≈ 1.0** (0.98 ~ 1.0) | 볼록이나 이산화로 hull 이 약간 큼 |
| **S3 링** | **≈ 0.75** | `5890.5 / 7853.98` — hull 은 꽉 찬 원판 |
| **S4 가로선** | **1.0** | 축퇴 hull = 자기 자신 |
| **S5 L자** | **≈ 0.87** | 아래 계산 ↓ |
| **S6 단일픽셀** | **1.0** | |
| **S7 빈 리전** | **0.0** | `F_c = 0` → 0 나눗셈 방어 |

**S5 L자의 hull 면적 (손계산)**
hull 꼭짓점 (row, col): `(0,0) (0,49) (50,99) (99,99) (99,0)`
픽셀 중심 기준 신발끈 공식 → **8551**
```
C(폴리곤) = 7500 / 8551 = 0.87709
```

### T-12. 정의 연쇄 항등식 (도형 무관)

기댓값 표와 별개로, **모든 도형에서 항상 성립해야 하는 등식**이다.
어느 한 오퍼레이터만 고치고 나머지를 안 고치는 회귀를 잡는다.

| # | 항등식 | 무엇을 잡는가 |
|---|---|---|
| **I-1** | `M**_invar · F² == M**` (세 항 전부) | §6 ↔ §7 정규화 연쇄 |
| **I-2** | `Ra == 2·sqrt(Ia/F)` , `Rb == 2·sqrt(Ib/F)` | §6 ↔ §8 정규화 연쇄 (`EA-1`) |
| **I-3** | `Ia >= Ib >= 0` , `Ra >= Rb >= 0` | 고유값 순서·반정치성 |
| **I-4** | `Anisometry == Ra/Rb` (`Rb > 0`) | §8 ↔ §9 |
| **I-5** | `StructureFactor == π·Ra²/A − 1` (`Rb > 0`) | §9 내부 정합 |
| **I-6** | `orientation ∈ {Phi, wrap(Phi+π)}` , `−π <= orientation < π` | §8 ↔ §10 + Assertion |
| **I-7** | `M11 == 0` 이고 `M20 == M02` 이면 `Phi == 0` 이고 `Ra == Rb` | 축퇴 처리 |

**I-2 가 가장 중요하다.** `elliptic_axis` 의 정규화를 `F²` 로 잘못 넣으면
`Ra` 는 `sqrt(F)` 배만큼 어긋나는데, 그것을 잡아 주는 것은 **정확값 표와 I-2 뿐**이다
(`Phi` 도 `Anisometry` 도 정규화에 둔감해서 못 잡는다).

### 확정 근거 — 실측 없이 원문 논리로 해소됨

**P-1.** 원문이 **"대각 인접 = √2"** 라고 명시한다. 픽셀 경계를 따라가는 모델(crack following)은
모든 스텝이 축평행 단위길이라 **√2 항이 원리적으로 존재할 수 없다.** 대각 스텝은 픽셀 중심을 잇는
체인코드에서만 발생하므로, √2 가중치의 존재 자체가 픽셀 중심 체인을 증명한다.

**P-2.** 문서상 Assertion 이 `Convexity <= 1` 이다. 폴리곤 면적을 쓰면 정사각형에서 `1.0203` 이 나와
**HALCON 자신의 Assertion 을 위반**한다. 또 `F_o` 가 픽셀 개수이므로 단위 일관성상 `F_c` 도 픽셀 개수여야 한다.

**P-3.** 원문 Attention 에 **"The contour of holes is not calculated"** 로 직접 명시되어 있다.

| `OR-2` | 없음 (범위 문제) | — | `[−π, π)` 로 접는다 | `GLIM_HALCON_ORIENTATION_WRAP` (1) |
